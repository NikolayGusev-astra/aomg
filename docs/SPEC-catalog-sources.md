# Спецификация: Каталог из нескольких источников (ADR-0002)

## Цель

Пользователь AOMG ищет MCP-серверы не только в официальном реестре, но и
в своих источниках: нейлдип (публичный RU), корпоративный каталог за
VPN/шлюзом (корп-каталог), любой JSON-манифест. Поиск — по выбранному
источнику, с бейджем доступности. Источник описывается в конфиге, без кода.

## Источники — спецификация форматов

### official (встроен, один)

Локальный дисковый индекс реестра (aomg/index.py). Поиск мгновенный,
обновление фоновое. В UI: таб «Реестр MCP».

### json (пользовательский, основной сценарий)

HTTP GET на url источника (через egress-группу источника, с headers).
Ожидаемый ответ — JSON одной из форм (детект по структуре):

```json
// Форма A: простой список
[{"name": "blender-mcp", "title": "Blender MCP",
  "description": "...", "url": "https://.../mcp"},
 {"name": "unreal-mcp", "command": "npx -y unreal-mcp"}]

// Форма B: обёртка
{"servers": [ ...те же записи... ]}
```

Поле записи: `name` (обязательно), `title`/`description` (опционально),
ровно одно из `url` (http-сервер) / `command` (stdio, строка целиком —
разбивается по пробелам на command+args). Опционально `headers` (объект),
`env` (объект). Поля секретов — `${VAR}`-плейсхолдеры, подставляются
стандартным механизмом конфига.

Ошибка формата → источник помечается «сломан» (бейдж в UI), не роняет
остальные.

### neuraldeep (встроен, можно скрыть)

Существующий RSC-адаптер (aomg/catalog.py::NeuralDeepSource). В UI:
таб «NeuralDeep (RU)» с бейджем «РФ-сервис».

### Корпоративный каталог (реальный кейс, host не публикуется)

Внутренний RAG-сервис с OpenAPI: `/openapi.json` публичный, эндпоинт
списка источников требует Bearer (проверено живьём: 401 без токена).
Но у него пока нет JSON-эндпоинта каталога MCP-серверов — до его появления
источник подключается через свой прокси-манифест (простой статический
JSON по форме A, лежит рядом с сервисом). В конфиге пользователя:

```yaml
catalog_sources:
  corp:
    type: json
    url: https://<внутренний-хост>/api/v1/mcp-servers
    group: vpn            # или corporate
    headers: {Authorization: "Bearer ${CORP_CATALOG_TOKEN}"}
```

## Конфиг

```yaml
catalog_sources:            # секция опциональна; нет секции = как сейчас
  neuraldeep: {hidden: false}
  corp:
    type: json
    url: https://<corp-catalog.example>/api/v1/mcp-servers
    group: vpn
    headers: {Authorization: "Bearer ${CORP_CATALOG_TOKEN}"}
```

Запись без `type` валидна только для встроенных имён (`neuraldeep`).
Неизвестное имя без `type` → warning при загрузке, источник пропускается.

## API панели

- `GET /admin/api/catalog/sources` — список источников:
  `[{name, type, url?, group, hidden, state: ok|error|unreachable, error?,
  count?, cached_at?}]`. state по последней попытке.
- `GET /admin/api/catalog?source=<name>&query=...` — поиск в выбранном
  источнике (без `source` — official, обратная совместимость).
- `POST /admin/api/catalog/sources` — добавить/обновить источник
  (имя, type, url, group, headers); `DELETE /admin/api/catalog/sources/<name>`
  — удалить (встроенные нельзя).
- Секреты в ответах API маскируются `***` (существующее правило).

## UI (страница /admin)

Один блок «Каталог» вместо поля «Найти в каталоге» в диалоге добавления:

- Табы по источникам (Реестр MCP · NeuralDeep · <кастомные>).
  У таба точка-индикатор: зелёная ok / красная error (с tooltip).
- Поле поиска + результаты в выбранном табе; карточка несёт
  `source` — при добавлении сервера это поле уходит в POST.
- Кнопка «Источники» рядом с табами → диалог списка: имя, тип, url,
  группа egress, состояние, кнопки «Добавить» / «Изменить» / «Удалить»
  (встроенные — только скрыть/показать neuraldeep).
- Форма источника: имя (slug), тип (json — единственный добавляемый),
  url, группа egress (селектор из существующих), заголовки (key/value,
  значения-секреты маскируются).
- Диалог добавления сервера: как сейчас, но поиск убран — вместо него
  кнопка «Найти в каталоге» открывает блок каталога; выбор карточки
  предзаполняет форму (существующий pick()).

## Тестирование

- Юнит: парсер JSON-источника (обе формы, ошибки формата), построение
  карточек, дедуп, скрытие neuraldeep, валидация конфига источников
  (неизвестное имя без type, секреты не логируются).
- Юнит: TTL-кэш JSON-источника (свежий → сеть не трогаем, протух → fetch,
  недоступен → старый кэш + state=unreachable).
- Интеграция (TestClient): GET sources, поиск per-source с подменой
  транспорта, 401 → state=unreachable + бейдж, добавление/удаление
  источника (yaml-запись, маскирование секрета).
- E2E-смоук вручную: реальный neuraldeep через адаптер; корп-каталог —
  ожидаемо 401 без токена → бейдж «нужен токен» (это честный результат,
  не падение).

## Критерии готовности

1. `catalog_sources` из README-примера поднимается без кода; corp-источник с токеном отдаёт записи в табе «corp».
2. Поиск в недоступном источнике даёт красный бейдж за ≤ таймаута источника
   (10с) и не влияет на другие табы.
3. Секреты источников не видны в ответах API и логах.
4. Обратная совместимость: старый конфиг без секции работает как раньше;
   существующий `/admin/api/catalog?query=` без `source` ищет в official.
5. Все новые пути покрыты тестами; полный набор зелёный.

## Не в этой версии

- Федеративный поиск по всем источникам (ADR-0002 отверг).
- HTML-адаптеры из UI (только кодом, neuraldeep — встроенный пример).
- Автодобавление источника по URL-странице без манифеста.
