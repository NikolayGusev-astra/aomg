# ADR-0003: Runtime-реестр серверов — один владелец Health

Статус: accepted, 2026-09-30

## Контекст

Аудит сессии 20260930_100646_31e2ee нашёл дефект, который ломает приложение
целиком, а не одну функцию.

`run.py` создаёт `healths = {n: Health() for n in cfg.servers}` и передаёт
один и тот же словарь **четырём** владельцам:

| поток | читает/пишет | где |
|---|---|---|
| watchdog (фоновый поток) | `healths[name]` | `aomg/watchdog.py:80` |
| gateway (uvicorn, N потоков) | `healths[name].record` | `aomg/gateway.py:59,69` |
| admin (HTTP-запрос) | `healths.pop(name)` | `aomg/admin.py:273` |
| run.py (старт) | создаёт | `run.py:69` |

`POST /admin/api/servers` (`admin.py:281`) добавляет запись в `cfg.servers`,
зывает `supervisor.ensure(name)` — и **не создаёт `Health`**. Воспроизведено:

```
KeyError: 'newsrv'
  File "aomg\watchdog.py", line 80, in watch_loop
    h = healths[name]
WATCHDOG ALIVE after runtime-added server: False
```

Следствия:
1. Первое же добавление MCP через панель **убивает watchdog навсегда** — поток
   падает с необработанным KeyError, мониторинг всех серверов замирает, трей и
   `/health` показывают застывший `reconnecting`.
2. Тот же KeyError в `gateway.py:59` → 500 вместо 504 при проксировании к
   новому серверу, если апстрим недоступен.
3. `healths` — общий изменяемый словарь без синхронизации между тремя потоками.
   `Health.record` мутирует `history` без лока. Удаление сервера через панель
   во время итерации watchdog — тот же KeyError.

Корень проблемы не в watchdog и не в admin, а в том, что у состояния
рантайма **нет владельца**: его параллельно конструируют четыре независимых
модуля, и ни один не отвечает за целостность.

## Решение

**`Supervisor` — единственный владелец рантайм-состояния серверов.**

Он уже владеет `ManagedServer` (процессами). Теперь он же владеет `Health`
и любыми мутациями обоих. Словарь `healths` как параметр, передаваемый
четырём модулям, **удаляется из сигнатур**.

```python
class Supervisor:
    managed: dict[str, ManagedServer]   # процессы (было)
    healths: dict[str, Health]          # состояние (стало владельцем)
    def add(name, spec) -> None         # атомарно: Health + ManagedServer
    def remove(name) -> None            # атомарно: stop + pop из обоих
    def health(name) -> Health | None   # None вместо KeyError
    def snapshot() -> list[tuple[str, Health]]   # для /health и иконки
```

Все мутации — под существующим `self._lock`. Все читатели идут через
`supervisor.health(name)` / `supervisor.snapshot()` и **не могут** получить
`KeyError`: отсутствие записи — это `None`, а не исключение.

Инварианты (проверяются тестами, `tests/test_runtime_registry.py`):

- **I1.** `name in supervisor.healths` ⟺ `name in supervisor.managed`
  ⟺ `name in cfg.servers`. Нарушение этого инварианта недостижимо извне:
  единственная точка мутации — `add`/`remove`.
- **I2.** Ни один модуль не обращается к `healths[...]` по индексу без
  `try`/`None`-проверки. `grep "healths\[" aomg/` пуст.
- **I3.** `snapshot()` возвращает согласованный срез под локом — `/health`
  никогда не показывает сервер, которого уже нет, и не падает на этом.

## Альтернативы, отвергнутые

- **`defaultdict(Health)`** — KeyError исчезает, но `cfg.servers`-владельцем
  остаётся кто-то другой, и Health для удалённого сервера продолжает жить в
  словаре. Проблема инварианта остаётся, симптом уходит.
- **`healths.setdefault(name, Health())` в вызывающем коде** — тот же дырявый
  паттерн в четвёртом месте; появление пятого места не остановить.
- **`threading.Lock` вокруг текущего словаря** — защищает от гонок, но не
  решает KeyError: записи в `healths` по-прежнему создаются вручную в
  не менее чем трёх местах.
- **Supervisor-as-service (отдельный поток + очередь команд)** — честнее
  изолирует, но для трей-приложения с 5–20 серверами это лишний IPC-слой;
  достаточно одного лока.

## Следствия

- Фикс P0 из аудита закрывается структурно, а не патчем в двух местах:
  добавить сервер корректно нельзя «наполовину».
- `run.py` теряет строку `healths = {...}`; сигнатуры `create_app`,
  `register_admin`, `start_watchdog`, `watch_loop`, `run_tray` меняются
  (упрощаются — параметров становится меньше).
- Трей-иконка и `/health` читают `snapshot()` — единый источник, порядок
  серверов стабилен (порядок конфига).
- Рефакторинг трогает 6 файлов, поэтому делается **первым** и отдельным
  коммитом: остальные фиксы аудита зависят от целостности `healths`.
