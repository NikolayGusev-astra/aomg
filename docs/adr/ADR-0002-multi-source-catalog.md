# ADR-0002: Каталог из нескольких источников — кастомные реестры, поиск по каждому

Статус: proposed, 2026-09-30

## Контекст

Каталог AOMG ищет в одном источнике — официальном реестре
registry.modelcontextprotocol.io. Реальные пользователи имеют свои источники:

- публичные агрегаторы: neuraldeep.ru (RU-сервисы), будущие подобные;
- корпоративные каталоги за VPN/корп-прокси (например, внутренний
  RAG-сервис с OpenAPI-эндпоинтом и Bearer-авторизацией; реальный хост
  в публичных доках не называется);
- просто URL-лист MCP-серверов (`/mcp`-страница или JSON-манифест).

Обратная связь от первого внешнего пользователя: «годная штука… интересно
добавить обращения к mcp-серверам Unreal Engine и Blender» — такие серверы
живут в сторонних каталогах, не в официальном реестре. Без поддержки
кастомных источников их не найти.

Разные источники требуют разный egress: официальный реестр — напрямую,
нейлдип — напрямую, корпоративный каталог — через VPN или корп-шлюз.
Существующие egress-группы AOMG (ADR-0001) уже решают маршрутизацию —
нужно связать источник каталога с группой.

## Решение

Единый интерфейс источника уже есть (`aomg/catalog.py`, `CatalogSource`).
Достраиваем поверх:

1. **Типы источников** (поле `type` в описании источника):
   - `official` — встроенный, один, реестр MCP (локальный индекс);
   - `json` — источник отдаёт JSON-манифест по HTTP (формат: список
     записей `{"name","title","description","url"|"command","headers"...}`,
     совместим с карточкой каталога); подходит для корпоративных каталогов
     с простым API и для «просто списка серверов»;
   - `html` — HTML-страница-каталог (как neuraldeep): парсинг адаптером.
     Встроенный адаптер neuraldeep остаётся примером; другие HTML-каталоги
     требуют своего адаптера — из UI добавляются только `json`-источники
     и нейлдип (встроенный).
2. **Реестр источников в конфиге** (`config.yaml` → `catalog_sources:`):
   имя, type, url, egress-группа, опционально headers с `${VAR}`-секретами
   (corp-каталог требует Bearer — секрет в User-окружении, не в файле).
   Встроенные: `official` (не отключаем), `neuraldeep` (можно скрыть).
3. **Поиск per-source**: UI — выпадающий список источников + поиск в
   выбранном; ответ помечен источником. У каждого источника свой
   egress (группа из конфига) — «напрямую / VPN / корп-шлюз» выбирается
   один раз при описании источника, не при каждом поиске.
4. **Кэш на источник**: официальный — дисковый индекс (уже есть);
   JSON-источники — TTL-кэш 24ч на диск рядом с индексом
   (`catalog-cache-<name>.json`), чтобы корпоративный каталог, доступный
   только в офисной сети, не ломал поиск вне её.
5. **GUI**: один экран «Каталог» с табами по источникам; у таба — бейдж
   доступности (ok / нет сети / нужен VPN); добавление источника —
   форма в настройках панели.

## Альтернативы, отвергнутые

- Федеративный поиск по всем источникам сразу (один запрос — три каталога):
  скрывает, ГДЕ найдено, путает при конфликтах имён, медленнее (таймаут
  самого тупого источника тормозит всех). Per-source табы честнее и проще.
- Единый «мета-реестр» прокси: лишний сервис, SPOF, не нужен для 3–5 источников.
- Поддержка произвольных HTML-каталогов из UI: каждый сайт — свой парсер,
  из UI это не конфигурируется честно. Оставляем как код-адаптеры.

## Следствия

- Добавление корпоративного источника = 6 строк в конфиге + выбор группы
  egress; никакого кода.
- Секреты источников не попадают в GUI-ответы (маскирование уже есть).
- Поиск в недоступном источнике не блокирует остальные (таймаут на источник).
- Версия схемы конфига не меняется: `catalog_sources` — опциональная
  секция, отсутствие = текущее поведение.
