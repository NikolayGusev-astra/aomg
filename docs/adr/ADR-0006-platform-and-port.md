# ADR-0006: Платформенная граница — Windows-only релиз, порт гейтвея с fallback

Статус: accepted, 2026-09-30

## Контекст

Две независимые проблемы, обе — про границу платформы и портов.

### A. Релиз отдаёт артефакты, которые не запустятся

`.github/workflows/build.yml` собирает матрицу `windows / ubuntu / macos`
и публикует три тарбола в релизе `v0.1.2`. Проверено по коду:

| место | что не так на POSIX |
|---|---|
| `aomg/supervisor.py:153` | `subprocess.CREATE_NO_WINDOW` — атрибута нет на Linux/macOS → `AttributeError` при спавне **первого** stdio-сервера |
| `aomg/supervisor.py:123` | путь жёстко `mcp-proxy.exe` для frozen |
| `aomg/tray.py:74` | `pystray` на Linux требует X11/DBus; в headless CI — падение |
| `run.py:96` | `os._exit(0)` вместо корректного завершения uvicorn |
| `run.py:42` | ветка `frozen and sys.stdout is None` — windows-only допущение |

Т.е. Linux/macOS-сборка компилируется (PyInstaller не проверяет
`CREATE_NO_WINDOW` на этапе сборки) и падает на первом же
`supervisor.start_all()`.

### B. Занятый порт = тишина

`run.py:65` жёстко пишет `gateway_port: 9300`; `gateway.py:103` —
`port=cfg.gateway_port` без обработки. На занятого порту uvicorn уходит
в молчание, в логе пользователя — `[Errno 10048] error while attempting to
bind on address ('127.0.0.1', 9300)` с нечитаемой кириллицей от
консольного кодировщика. Пользователь спросил «порт может выбирать
свободный?» — ответа нет. Свободный порт у нас уже умеет искать
`supervisor._free_port()` — но только для дочерних прокси.

## Решение

### A. Релиз — Windows-only, честно

Матрица `build.yml` остаётся windows-only до появления
`aomg/platform.py` со слоем `creationflags` / путём к прокси /
инициализацией трея. ADR фиксирует **условие** возврата кроссплатформы,
а не обещание.

В `docs/SDD.md` и README добавляется явное «AOMG — Windows-приложение»
и раздел «Почему нет Linux/macOS-сборки» со ссылкой на этот ADR: иначе
отсутствие сборок выглядит как недоделка, а не как решение.

`pystray` в `requirements.txt` помечается `; sys_platform == "win32"`.

### B. Порт гейтвея: выбор свободного + честная диагностика

```python
def resolve_gateway_port(preferred: int, host="127.0.0.1") -> int
```

Порядок: пробуем `preferred`; если занят — `_free_port()`; если и он
занят (гонка) — пробуем следующий свободный, до 20 попыток. Результат
пишется в конфиг **только если** в конфиге не было явного
`gateway_port` (пользовательский выбор не перебиваем молча).

Если свободного порта нет — `AOMG` печатает в лог понятную строку с
списком занятых портов и завершает работу кодом 2, а не падает стеком
uvicorn.

Диагностика: `logs/aomg.log` получает строку
`[aomg] gateway port 9300 busy, using 9312`, а трей-подсказка и
`/health` показывают фактический порт (`cfg.gateway_port` — единственный
источник, `admin.py:424` перестаёт хардкодить 9300 в тексте легенды).

Инварианты (тесты `tests/test_gateway_port.py`):

- **I1.** Занятый `preferred` → возвращается другой свободный порт.
- **I2.** Явно заданный в конфиге порт **не** переписывается, если он
  занят — пользователь получает диагностику и ненулевой код выхода,
  а не тихую смену адреса (иначе агент по старой ссылке не найдёт шлюз).
- **I3.** Все порты заняты → исключение с текстом, а не
  `OSError: [Errno 10048]`.
- **I4.** В HTML-легенде панели и в `status_line` трея — фактический порт
  из конфига, не константа.

## Альтернативы, отвергнутые

- **Держать три сборки, «кто-нибудь починит»** — публичный релиз с
  заведомо мёртвыми Linux/macOS-артефактами хуже, чем их отсутствие.
- **Слой платформы прямо сейчас** (`if os.name == 'nt'`) — честно, но это
  отдельная работа (трей, автозапуск, иконки, пути), не повод делать
  вид, что релиз кроссплатформенный.
- **Игнорировать занятый порт, показывать ошибку в трее** — пользователь
  не понимает, почему агент не видит MCP; авто-выбор порта решает
  автоматически.
- **Менять порт при конфликте всегда** (без разбора «явный/неявный») —
  ломает ссылку агента, который уже настроен на 9300. Отвергнуто (I2).

## Следствия

- Релиз `v0.1.3` содержит один тарбол (Windows) + инсталлятор; в
  release notes — раздел про платформу.
- `CREATE_NO_WINDOW` остаётся в коде как есть (Windows-only релиз), но
  получает комментарий со ссылкой на ADR — иначе «случайная» константа
  выглядит как баг.
- `run.py` при первом старте пишет `gateway_port` в автосозданный конфиг
  уже проверенным значением.
