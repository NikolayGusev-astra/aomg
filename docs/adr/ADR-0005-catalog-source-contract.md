# ADR-0005: Единый интерфейс источника каталога и его egress

Статус: accepted, 2026-09-30

## Контекст

ADR-0002 вводил мульти-источниковый каталог и обещал три вещи:
типы источников (`official` / `json` / встроенный html-адаптер), привязку
источника к egress-группе и «поиск в недоступном источнике не блокирует
остальные». Аудит сессии 20260930_100646_31e2ee показал, что реализация
разошлась с ADR по всем трём пунктам.

**1. Два несовместимых контракта.** `aomg/catalog.py` объявляет
`CatalogSource` с `list_items()` / `get_item()`. `admin.py` и
`json_source.py` ждут `.search(query, limit)`, `.state`, `.error`.
`NeuralDeepSource` не имеет `search` вообще — подтверждено на живой
установленной сборке, `logs/aomg.log`:

```
File "aomg\admin.py", line 215, in api_catalog
AttributeError: 'NeuralDeepSource' object has no attribute 'search'
```

То есть встроенный источник **не работает**, при этом `_source_public`
(`admin.py:145`) рисует ему `state: "ok"` — UI показывает зелёный
недоступный источник. Ровно то, что пользователь описал как «источники
горят зелёным, а при выборе реестр недоступен».

**2. Egress-группа источника игнорируется.** `json_source.py:94`:

```python
def _fetch_network(self):
    with httpx.Client(timeout=TIMEOUT, trust_env=False, ...) as c:
```

Ни `proxy=`, ни чтения `spec.group`. ADR-0002 и SPEC обещали «HTTP GET на
url источника (через egress-группу источника)». Корп-каталог за
VPN/корп-шлюзом не скачается — а UI покажет «доступен», потому что
состояние ленивое и никогда не проверялось.

**3. `_build_catalog_sources` пересоздаёт все источники на каждом
upsert/remove** (`admin.py:186,199`) — in-memory кэш `JsonSource._mem` и
состояние `state/error` выбрасываются на ровном месте.

**4. Плоский счётчик вместо пагинации.** `limit=20 → 50`, «магическое
число 10» в списке. Пользователь не может увидеть 51-ю карточку.

**5. Блокирующий сетевой вызов в sync-эндпоинте.** `registry.search()`
(timeout 20 с) вызывается из `def api_catalog(...)`. Замерено:

```
blender ERR ReadTimeout 20461 ms
```

Это и есть «долгий поиск по каталогу», с которого началась сессия.

## Решение

### 5.1 Один контракт

```python
class CatalogSource(Protocol):
    name: str
    def search(self, query: str, limit: int = 50) -> list[dict]: ...
    def status(self) -> tuple[str, str | None]:   # (state, error)
```

`state`/`error` становятся **методом**, а не полями: у источника может
 быть кэш, и «доступен» — это результат последней попытки, а не константа.

Адаптеры: `IndexSource` (official, поверх `CatalogIndex`),
`JsonSource`, `NeuralDeepSource`. `catalog.py` перестаёт быть вторым
реестром классов и становится **адаптером** neuraldeep с новым контрактом.
`OfficialSource` из `catalog.py` удаляется — его роль занял `IndexSource`
(локальный индекс), прямая запись в реестр из UI больше не нужна.

### 5.2 Egress — часть источника

`JsonSource` получает `proxy: str | None`, вычисленный из
`spec.group` через `cfg.groups` при построении источников. Секреты и
маршрут — на construction, не на каждый запрос. Это исполняет обещание
ADR-0002 без новых полей в схеме конфига.

### 5.3 Источники не пересоздаются

`_build_catalog_sources` становится **инкрементальным**: upsert/delete
меняют один элемент `app.state.catalog_sources`, остальные объекты (и их
кэши) сохраняются. При смене состава `catalog_sources` в конфиге —
полная пересборка (редкий путь).

### 5.4 Пагинация вместо магического числа

Ответ `/admin/api/catalog` получает `limit` (default 50, max 200) и
`offset`; ответ — `{items, total, limit, offset, has_more}`. UI добавляет
кнопку «ещё 50». Пустой индекс больше не означает «реестр недоступен»:
при пустом результате и доступном реестре UI показывает счётчик
«найдено N, показано M», а не «ничего не найдено».

### 5.5 Живой реестр — async, с потолком

`registry.search` переезжает на `httpx.AsyncClient` с `timeout=3.0`
(connect 2.0) и вызывается из `async def api_catalog`. Индекс остаётся
синхронным, но чтение 2.4 МБ JSON на каждый keystroke уходит в
**in-memory кэш**, инвалидируемый по `mtime` файла: 33–48 мс → ~0 мс.

Инварианты (тесты `tests/test_catalog_contract.py`):

- **I1.** Каждый источник в `app.state.catalog_sources` имеет `search`
  и `status`. Рефлексия по `app.state.catalog_sources` в тесте — источник
  с другим контрактом нельзя зарегистрировать.
- **I2.** `JsonSource` с непустой группой открывает клиент с `proxy=`
  этой группы; `trust_env=False` сохраняется.
- **I3.** Upsert источника не меняет `id()`/состояние других источников.
- **I4.** Живой фолбэк реестра укладывается в 5 с при недоступной сети и
  возвращает `notice`, а не висит.
- **I5.** Ответ каталога содержит `total` и `has_more`; при `offset>0`
  items — срез, а не первые N.

## Альтернативы, отвергнутые

- **Два интерфейса с адаптером в `admin.py`** (`if hasattr(src,'search')`)
  — ровно то, что привело к `AttributeError` в проде; отсечка только
  отодвинет падение.
- **Проверять `hasattr` при старте и показывать «источник сломан»** —
  полезно как страховка, но контракт всё равно нужно чинить; делаем
  отдельным assert-тестом (I1) вместо рантайм-защиты.
- **Переименовать `search` в `list_items` в `JsonSource`** — ломает
  `admin.py` и тесты, не даёт ничего.
- **Перенести блокирующий httpx в threadpool** — оставляет 20 с вместо 3 с;
  дешёвый таймаут честнее.
- **Кэш индекса в SQLite** — 2.4 МБ, mtime-инвалидация в памяти
  достаточна; лишняя зависимость.

## Следствия

- `aomg/catalog.py` перестаёт быть мёртвым кодом и перестаёт быть вторым
  контрактом; `tests/test_catalog.py` переписывается под новый контракт.
- SPEC и ADR-0002 становятся правдой; расхождение «документ — код»
  закрыто.
- Каталог в панели перестаёт показывать «доступен» вслепую: у каждого
  источника статус — результат последней реальной попытки.
- Правки локальны: `catalog.py`, `json_source.py`, `index.py`
  (кэш), `admin.py` (контракт, пагинация, async), тесты.
